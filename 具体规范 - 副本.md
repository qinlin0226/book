# AI 操作 Java 后端代码通用规范

> **版本**: v1.0  
> **适用范围**: AI 辅助生成、审查、重构 Java 后端代码（Spring Boot + Spring Cloud + MyBatis-Plus + Lombok / 微服务 / 单体应用）  
> **目标**: 确保 AI 生成的代码具备一致性、可维护性、安全性与高性能

---

## 一、代码风格与格式规范

### 1.1 命名规范
| 类型 | 规范 | 示例 |
|------|------|------|
| **类名** | 大驼峰（UpperCamelCase），名词 | `UserService`, `OrderRepository` |
| **方法名** | 小驼峰（lowerCamelCase），动词开头 | `getUserById()`, `processOrder()` |
| **变量名** | 小驼峰，语义清晰 | `userList`, `isActive` |
| **常量名** | 全大写，下划线分隔 | `MAX_RETRY_COUNT`, `DEFAULT_PAGE_SIZE` |
| **包名** | 全小写，域名倒序 | `com.company.module.service` |
| **布尔变量** | 避免否定命名 | `isEnabled` ✔️ / `isNotFound` ❌ |

### 1.2 代码格式
- **缩进**: 4 个空格（禁用 Tab）
- **行宽**: 单行不超过 120 字符
- **括号**: K&R 风格，左括号不换行
- **空行**: 方法间保留 1 空行，逻辑段间按需空行
- **导入**: 使用 `*` 仅当同一包下类超过 5 个；禁止 `import java.util.*` 滥用

```java
// ✅ 推荐
public class UserService {
    private static final int MAX_RETRY = 3;

    public User getUserById(Long id) {
        if (id == null || id <= 0) {
            throw new IllegalArgumentException("Invalid user ID");
        }
        return userRepository.findById(id)
            .orElseThrow(() -> new UserNotFoundException(id));
    }
}
```

### 1.3 Lombok 使用规范

#### 1.3.1 允许使用的注解
| 注解 | 用途 | 注意 |
|------|------|------|
| `@Getter` / `@Setter` | 生成访问器 | 类级别或字段级别 |
| `@ToString` | 生成 toString | 必须排除敏感字段 |
| `@EqualsAndHashCode` | 生成 equals/hashCode | 仅用于 VO/DTO，Entity 谨慎使用 |
| `@Data` | 组合注解（@Getter @Setter @ToString @EqualsAndHashCode @RequiredArgsConstructor） | **禁止在 Entity 直接使用** |
| `@NoArgsConstructor` | 无参构造 | Entity / DTO 常用 |
| `@AllArgsConstructor` | 全参构造 | 谨慎使用，字段顺序变更影响构造参数 |
| `@RequiredArgsConstructor` | 必需参数构造（final 字段） | **Service / Controller 推荐** |
| `@Builder` | 构建者模式 | 配合 `@NoArgsConstructor` + `@AllArgsConstructor` |
| `@Slf4j` | 日志声明 | 统一使用，禁止 `@Log4j` |

#### 1.3.2 Entity 类 Lombok 规范
```java
// ✅ 推荐：Entity 显式控制，避免 @Data 副作用
@Getter
@Setter
@ToString(exclude = {"password", "salt"})  // 排除敏感字段
@EqualsAndHashCode(of = {"id"})             // 仅基于主键
@NoArgsConstructor
@AllArgsConstructor
@TableName("t_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String username;
    private String password;  // 被 @ToString 排除
}

// ❌ 禁止：@Data 在 Entity 上会产生全字段 equals/hashCode/toString
@Data
@TableName("t_user")
public class User { ... }
```

**Entity 禁用 `@Data` 原因**:
1. `@EqualsAndHashCode` 基于所有字段 → 懒加载字段可能触发 N+1 / 异常
2. `@ToString` 打印所有字段 → 可能暴露密码等敏感信息
3. `@RequiredArgsConstructor` 生成 final 字段构造 → 与 MyBatis 反射实例化冲突

#### 1.3.3 DTO / VO / BO 类规范
```java
// ✅ DTO：接收前端参数，需要 Setter
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class UserDTO {
    @NotBlank(message = "用户名不能为空")
    private String username;

    @Email(message = "邮箱格式不正确")
    private String email;
}

// ✅ VO：返回给前端，通常只读
@Getter
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class UserVO {
    private Long id;
    private String username;
    private String email;
    // 不包含密码等敏感字段
}
```

#### 1.3.4 Service / Controller 构造注入
```java
// ✅ 推荐：@RequiredArgsConstructor + final 字段（无需 @Autowired）
@Service
@RequiredArgsConstructor
@Slf4j
public class UserService {
    private final UserMapper userMapper;
    private final RedisTemplate<String, Object> redisTemplate;
    private final UserConverter userConverter;
}

// ❌ 禁止：字段注入
@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;  // 测试困难，不推荐
}
```

#### 1.3.5 Lombok 配置（lombok.config）
在项目根目录创建 `lombok.config`:
```properties
# 禁止在生成的代码中使用 @Generated 注解（避免代码覆盖工具忽略）
lombok.addLombokGeneratedAnnotation = true

# 禁止 @ToString 调用父类 toString
lombok.toString.callSuper = call

# 禁止 @EqualsAndHashCode 调用父类
lombok.equalsAndHashCode.callSuper = call

# 禁止生成 @ConstructorProperties（Java 9+ 兼容性）
lombok.anyConstructor.addConstructorProperties = false
```

#### 1.3.6 Lombok 禁止项
- ❌ 禁止在 Entity 上使用 `@Data`
- ❌ 禁止 `@ToString` 不排除敏感字段（密码、Token、手机号）
- ❌ 禁止 `@EqualsAndHashCode` 在 Entity 上基于全字段
- ❌ 禁止 `@AllArgsConstructor` 在字段频繁变更的类上使用
- ❌ 禁止 `@SneakyThrows` 滥用（仅用于必须兼容的受检异常场景）
- ❌ 禁止 `@Cleanup`（使用 Try-With-Resources 替代）

## 二、架构与设计规范

### 2.1 分层架构（Layered Architecture）
```
Controller → Service → Repository/Mapper → Entity/PO
    ↓           ↓            ↓
   DTO        BO/VO      DO/Entity
```

**强制分层原则**:
- **Controller**: 仅处理 HTTP 请求/响应，禁止业务逻辑
- **Service**: 承载业务逻辑，禁止直接操作数据库（通过 Repository）
- **Repository/DAO**: 仅数据访问，禁止包含业务判断
- **Entity/PO**: 与数据库表映射，禁止包含业务方法

### 2.2 DTO / VO / BO 使用规范
| 对象 | 用途 | 规则 |
|------|------|------|
| **DTO** | 层间数据传输 | Controller ↔ Service 间使用 |
| **VO** | 视图展示 | 仅返回给前端的数据结构 |
| **BO** | 业务对象 | Service 层内部复杂逻辑封装 |
| **PO/Entity** | 持久化对象 | 仅用于数据库交互 |

**禁止**: 直接返回 Entity 给前端；禁止跨层混用对象类型。

### 2.3 接口设计（API 规范）
- **RESTful 风格**: 使用 HTTP 动词表达操作语义
  - `GET /api/v1/users` — 查询列表
  - `GET /api/v1/users/{id}` — 查询详情
  - `POST /api/v1/users` — 创建
  - `PUT /api/v1/users/{id}` — 全量更新
  - `PATCH /api/v1/users/{id}` — 局部更新
  - `DELETE /api/v1/users/{id}` — 删除
- **版本控制**: URL 路径包含版本号 `/api/v1/...`
- **统一响应格式**:
```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1713862800000
}
```

## 二之一、Spring Cloud 微服务架构规范

### 2.4 微服务拆分原则
| 原则 | 说明 |
|------|------|
| **单一职责** | 每个服务只负责一个明确的业务能力（如用户服务、订单服务） |
| **高内聚低耦合** | 服务间通过 API 通信，禁止直接访问其他服务数据库 |
| **独立部署** | 每个服务独立打包、独立发布、独立扩缩容 |
| **数据隔离** | 每个服务拥有独立数据库（Database per Service），禁止跨库 JOIN |

### 2.5 技术栈选型（Spring Cloud 202x.x）
| 组件 | 推荐方案 | 说明 |
|------|----------|------|
| **服务注册与发现** | Nacos Discovery | 替代 Eureka，支持配置中心一体化 |
| **配置中心** | Nacos Config / Spring Cloud Config | 推荐 Nacos，支持热更新 |
| **服务网关** | Spring Cloud Gateway | 替代 Zuul，响应式高性能 |
| **负载均衡** | Spring Cloud LoadBalancer | 替代 Ribbon |
| **服务调用** | OpenFeign + 负载均衡 | 声明式 HTTP 客户端 |
| **熔断降级** | Sentinel / Resilience4j | 推荐 Sentinel，支持流量控制 |
| **分布式事务** | Seata | AT / TCC / Saga 模式 |
| **链路追踪** | Micrometer Tracing + Brave / SkyWalking | 推荐 SkyWalking |
| **消息驱动** | Spring Cloud Stream + RocketMQ / Kafka | 异步解耦 |

### 2.6 项目结构规范（多模块微服务）
```
project-parent/                    # 父 POM，统一管理依赖版本
├── pom.xml
├── project-common/                # 公共模块（工具类、常量、异常定义）
│   ├── common-core/
│   ├── common-web/
│   └── common-mybatis-plus/
├── project-gateway/               # 网关服务（Spring Cloud Gateway）
├── project-auth/                  # 认证授权中心（OAuth2 / JWT）
├── project-user/                  # 用户服务
│   ├── user-api/                  # API 模块（Feign 接口、DTO）
│   ├── user-service/              # 业务实现
│   └── user-start/                # 启动模块
├── project-order/                 # 订单服务
│   ├── order-api/
│   ├── order-service/
│   └── order-start/
└── project-admin/                 # 监控管理（Spring Boot Admin）
```

**模块依赖规则**:
- `xxx-api` 模块：仅包含 Feign 接口、DTO、常量，**禁止依赖 Spring Boot Starter**
- `xxx-service` 模块：业务实现，依赖 `xxx-api` + `common-*`
- `xxx-start` 模块：仅包含启动类 + `application.yml`，依赖 `xxx-service`
- **禁止循环依赖**：A-service 依赖 B-api，B-service 禁止依赖 A-api（通过事件或第三方聚合）

### 2.7 服务命名与端口规范
| 服务类型 | 命名规则 | 端口规则 |
|----------|----------|----------|
| 网关 | `gateway` | 8080 |
| 认证中心 | `auth-service` | 9000 |
| 业务服务 | `{biz}-service` | 9xxx（如用户 9100，订单 9200） |
| 管理端 | `admin-service` | 9900 |

```yaml

server:
```

## 二之二、Spring Cloud Gateway 网关规范

### 2.8 网关职责
- **路由转发**: 统一入口，按 Path/Header 路由到下游服务
- **鉴权前置**: JWT 校验、Token 刷新、黑名单拦截
- **限流防护**: 基于 Sentinel 或 Redis 限流
- **日志追踪**: 注入 traceId，记录请求/响应日志
- **跨域处理**: 统一配置 CORS，下游服务不再处理

### 2.9 Gateway 配置规范
```java
@Configuration
public class GatewayConfig {

    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
            // 用户服务路由
            .route("user-service", r -> r.path("/api/v1/users/**", "/api/v1/auth/**")
                .filters(f -> f
                    .stripPrefix(0)
                    .circuitBreaker(config -> config
                        .setName("userServiceCircuitBreaker")
                        .setFallbackUri("forward:/fallback/user"))
                    .requestRateLimiter(config -> config
                        .setRateLimiter(redisRateLimiter())
                        .setKeyResolver(exchange -> Mono.just(
                            exchange.getRequest().getHeaders().getFirst("X-User-Id")))))
                .uri("lb://user-service"))
            // 订单服务路由
            .route("order-service", r -> r.path("/api/v1/orders/**")
                .filters(f -> f.stripPrefix(0))
                .uri("lb://order-service"))
            .build();
    }
}
```

**路由命名规则**: `{biz}-service`，与 `spring.application.name` 保持一致  
**路径规范**: 网关透传完整路径，下游服务 Controller 路径与网关配置一致  
**熔断配置**: 每个下游服务独立熔断器，fallback 返回统一错误格式

### 2.10 全局过滤器规范
```java
@Component
@Order(-1)  // 最高优先级
@Slf4j
public class GatewayGlobalFilter implements GlobalFilter {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        String traceId = Optional.ofNullable(request.getHeaders().getFirst("X-Trace-Id"))
            .orElse(UUID.randomUUID().toString().replace("-", ""));

        // 注入 traceId 到请求头和 MDC
        ServerHttpRequest mutatedRequest = request.mutate()
            .header("X-Trace-Id", traceId)
            .build();

        exchange.getAttributes().put("startTime", System.currentTimeMillis());

        return chain.filter(exchange.mutate().request(mutatedRequest).build())
            .then(Mono.fromRunnable(() -> {
                Long startTime = exchange.getAttribute("startTime");
                if (startTime != null) {
                    long duration = System.currentTimeMillis() - startTime;
                    log.info("Gateway request completed, traceId={}, path={}, duration={}ms",
                        traceId, request.getPath(), duration);
                }
            }));
    }
}
```

**过滤器优先级**:
| 顺序 | 过滤器 | 职责 |
|------|--------|------|
| -3 | TraceId 注入 | 生成/透传 traceId |
| -2 | JWT 校验 | Token 解析、黑名单校验 |
| -1 | 日志记录 | 请求/响应日志、耗时统计 |
| 0 | 限流 | Sentinel / Redis 限流 |
| 1 | 路由 | 转发到下游服务 |

## 二之三、OpenFeign 服务调用规范

### 2.11 Feign 接口定义（xxx-api 模块）
```java
// user-api 模块
@RequestMapping("/api/v1/users")
public interface UserFeignApi {

    @GetMapping("/{id}")
    Result<UserVO> getUserById(@PathVariable("id") Long id);

    @PostMapping
    Result<Long> createUser(@RequestBody @Valid UserDTO dto);

    @GetMapping
    Result<IPage<UserVO>> getUserPage(
        @RequestParam("page") int page,
        @RequestParam("size") int size,
        @RequestParam(value = "keyword", required = false) String keyword);
}

// Feign 客户端（可放在 api 模块或单独 feign 模块）
@FeignClient(
    name = "user-service",
    fallbackFactory = UserFeignClientFallbackFactory.class,
    configuration = FeignConfig.class
)
public interface UserFeignClient extends UserFeignApi {
}
```

**Feign 接口规范**:
- API 接口与 Feign 客户端分离：API 定义在 `xxx-api` 模块，Feign 客户端可继承或单独定义
- `@FeignClient` 的 `name` 必须与目标服务 `spring.application.name` 一致
- **必须配置 fallback / fallbackFactory**，禁止服务降级时直接抛异常
- 接口参数必须使用 `@RequestParam`、`@PathVariable`、`@RequestBody` 显式注解

### 2.12 Feign 降级（FallbackFactory）
```java
@Component
@Slf4j
public class UserFeignClientFallbackFactory implements FallbackFactory<UserFeignClient> {

    @Override
    public UserFeignClient create(Throwable cause) {
        log.error("User service call failed", cause);

        return new UserFeignClient() {
            @Override
            public Result<UserVO> getUserById(Long id) {
                return Result.fail(ErrorCode.SERVICE_UNAVAILABLE, "用户服务暂不可用");
            }

            @Override
            public Result<Long> createUser(UserDTO dto) {
                return Result.fail(ErrorCode.SERVICE_UNAVAILABLE, "用户服务暂不可用");
            }

            @Override
            public Result<IPage<UserVO>> getUserPage(int page, int size, String keyword) {
                return Result.fail(ErrorCode.SERVICE_UNAVAILABLE, "用户服务暂不可用");
            }
        };
    }
}
```

### 2.13 Feign 配置
```java
@Configuration
public class FeignConfig {

    @Bean
    public RequestInterceptor feignRequestInterceptor() {
        return template -> {
            // 透传 traceId
            String traceId = MDC.get("traceId");
            if (StringUtils.isNotBlank(traceId)) {
                template.header("X-Trace-Id", traceId);
            }

            // 透传 Token
            ServletRequestAttributes attributes = (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
            if (attributes != null) {
                String token = attributes.getRequest().getHeader("Authorization");
                if (StringUtils.isNotBlank(token)) {
                    template.header("Authorization", token);
                }
            }
        };
    }

    @Bean
    public Retryer feignRetryer() {
        // 重试策略：初始间隔 100ms，最大间隔 1s，最多重试 3 次（不含首次）
        return new Retryer.Default(100, 1000, 3);
    }

    @Bean
    public ErrorDecoder feignErrorDecoder() {
        return (methodKey, response) -> {
            if (response.status() == 404) {
                return new BusinessException(ErrorCode.SERVICE_NOT_FOUND);
            }
            if (response.status() == 503) {
                return new BusinessException(ErrorCode.SERVICE_UNAVAILABLE);
            }
            return new BusinessException(ErrorCode.REMOTE_CALL_ERROR);
        };
    }
}
```

**Feign 调用规范**:
- **超时配置**: 连接超时 5s，读取超时 10s（避免长时间阻塞）
- **重试策略**: 默认重试 3 次，仅对 GET 请求重试（幂等性）
- **上下文透传**: traceId、Token、租户 ID 等必须透传到下游
- **禁止**: Feign 接口中写业务逻辑；禁止同步调用链过长（超过 3 层服务调用考虑异步或聚合）

## 二之四、Sentinel 熔断降级规范

### 2.14 熔断规则配置
```java
@Configuration
public class SentinelConfig {

    @PostConstruct
    public void initRules() {
        List<DegradeRule> rules = new ArrayList<>();

        // 慢调用比例熔断
        DegradeRule slowCallRule = new DegradeRule("getUserById")
            .setGrade(CircuitBreakerStrategy.SLOW_REQUEST_RATIO.getType())
            .setCount(500)           // 慢调用阈值 500ms
            .setTimeWindow(30)       // 熔断持续时间 30s
            .setSlowRatioThreshold(0.5)  // 慢调用比例阈值 50%
            .setMinRequestAmount(10);    // 最小请求数
        rules.add(slowCallRule);

        // 异常比例熔断
        DegradeRule errorRule = new DegradeRule("createUser")
            .setGrade(CircuitBreakerStrategy.ERROR_RATIO.getType())
            .setCount(0.5)           // 异常比例阈值 50%
            .setTimeWindow(30)
            .setMinRequestAmount(10);
        rules.add(errorRule);

        DegradeRuleManager.loadRules(rules);
    }
}
```

**熔断策略选择**:
| 策略 | 适用场景 | 配置要点 |
|------|----------|----------|
| **慢调用比例** | 服务响应变慢（如数据库慢查询） | 阈值根据接口 P99 设置 |
| **异常比例** | 服务不稳定（如依赖服务故障） | 比例阈值 50%~80% |
| **异常数** | 低 QPS 服务 | 直接指定异常数量 |

### 2.15 流控规则（限流）
```java
@SentinelResource(
    value = "createOrder",
    blockHandler = "createOrderBlockHandler",
    fallback = "createOrderFallback"
)
public Long createOrder(OrderDTO dto) {
    // 业务逻辑
}

// 限流处理（QPS 超限）
public Long createOrderBlockHandler(OrderDTO dto, BlockException ex) {
    log.warn("Order creation rate limited, dto={}", dto);
    throw new BusinessException(ErrorCode.RATE_LIMITED, "系统繁忙，请稍后重试");
}

// 降级处理（异常/熔断）
public Long createOrderFallback(OrderDTO dto, Throwable ex) {
    log.error("Order creation failed, fallback triggered", ex);
    // 异步记录失败订单，后续补偿
    orderFailLogService.record(dto);
    throw new BusinessException(ErrorCode.ORDER_CREATE_FAILED, "订单提交失败，请稍后重试");
}
```

**Sentinel 使用规范**:
- **资源命名**: `{className}/{methodName}` 或业务语义名（如 `createOrder`）
- **blockHandler**: 处理限流/降级，参数必须与原方法一致 + `BlockException`
- **fallback**: 处理业务异常，参数必须与原方法一致 + `Throwable`
- **禁止**: blockHandler / fallback 中再调用 Sentinel 资源（避免循环）

## 二之五、分布式事务（Seata）规范

### 2.16 Seata 使用场景
| 场景 | 推荐模式 | 说明 |
|------|----------|------|
| 简单跨服务事务 | **AT 模式** | 自动补偿，侵入性低 |
| 复杂业务 / 金融 | **TCC 模式** | 手动实现 try/confirm/cancel |
| 长事务 /  Saga | **Saga 模式** | 状态机引擎，适合长流程 |

### 2.17 AT 模式规范
```java
@Service
@RequiredArgsConstructor
@Slf4j
public class OrderService {

    private final OrderMapper orderMapper;
    private final UserFeignClient userFeignClient;
    private final StockFeignClient stockFeignClient;

    @GlobalTransactional(name = "create-order", rollbackFor = Exception.class)
    public Long createOrder(OrderDTO dto) {
        // 1. 创建订单（本地事务）
        Order order = orderConverter.toEntity(dto);
        order.setStatus(OrderStatus.PENDING);
        orderMapper.insert(order);

        // 2. 扣减库存（远程调用）
        Result<Void> stockResult = stockFeignClient.deduct(dto.getSkuId(), dto.getQuantity());
        if (!stockResult.isSuccess()) {
            throw new BusinessException(ErrorCode.STOCK_INSUFFICIENT);
        }

        // 3. 扣减余额（远程调用）
        Result<Void> balanceResult = userFeignClient.deductBalance(dto.getUserId(), dto.getAmount());
        if (!balanceResult.isSuccess()) {
            throw new BusinessException(ErrorCode.BALANCE_INSUFFICIENT);
        }

        // 4. 更新订单状态
        order.setStatus(OrderStatus.PAID);
        orderMapper.updateById(order);

        log.info("Order created successfully, orderId={}", order.getId());
        return order.getId();
    }
}
```

**Seata 使用规范**:
- **全局事务入口**: 仅在聚合服务或编排层使用 `@GlobalTransactional`，底层服务使用本地 `@Transactional`
- **事务命名**: `name = "{biz}-{action}"`，全局唯一
- **回滚条件**: 显式配置 `rollbackFor = Exception.class`
- **禁止**: 在 `@GlobalTransactional` 中调用异步方法（线程切换导致上下文丢失）
- **注意**: AT 模式要求表必须有主键，且不支持复杂 SQL（如多表 JOIN UPDATE）

## 三、异常处理规范

### 3.1 异常分层
```
BusinessException（业务异常）→ 返回 400/422
SystemException（系统异常）→ 返回 500
AuthException（认证异常）→ 返回 401/403
ValidationException（参数校验）→ 返回 400
```

### 3.2 处理原则
- **禁止裸抛 `Exception` / `RuntimeException`**: 必须自定义业务异常
- **禁止吞没异常**: 禁止空 `catch` 块
- **日志记录**: 异常必须记录堆栈，`log.error("Operation failed, userId={}", userId, e)`
- **前端友好**: 对外暴露的 message 不得包含内部堆栈或敏感信息

```java
// ✅ 推荐
try {
    orderService.process(orderId);
} catch (OrderNotFoundException e) {
    log.warn("Order not found, orderId={}", orderId);
    throw new BusinessException(ErrorCode.ORDER_NOT_FOUND, "订单不存在");
} catch (Exception e) {
    log.error("Process order failed, orderId={}", orderId, e);
    throw new SystemException(ErrorCode.SYSTEM_ERROR, "系统繁忙，请稍后重试");
}
```

## 四、安全规范

### 4.1 输入校验
- **JSR-380 (Bean Validation)**: 使用 `@NotNull`, `@Size`, `@Pattern` 等注解
- **自定义校验**: 复杂规则使用 `Validator` 接口实现
- **防 SQL 注入**: 强制使用参数化查询（MyBatis `#{}` / JPA 参数绑定）
- **防 XSS**: 对前端输入进行 HTML 转义，输出使用 `Content-Type: application/json`

### 4.2 敏感数据处理
- **密码**: 必须使用 BCrypt / Argon2 哈希，禁止明文存储或 MD5/SHA1
- **密钥**: 禁止硬编码，使用配置中心或环境变量注入
- **日志脱敏**: 身份证号、手机号、银行卡号必须脱敏输出
  - 手机号: `138****8888`
  - 身份证号: `110101********1234`
- **接口鉴权**: 敏感接口必须校验 JWT / OAuth2 Token，使用 Spring Security

### 4.3 其他安全
- **CSRF**: 非 GET 请求必须校验 CSRF Token 或使用 SameSite Cookie
- **CORS**: 白名单配置，禁止 `Access-Control-Allow-Origin: *` 生产环境
- **文件上传**: 限制类型、大小，存储路径禁止用户控制，使用 UUID 重命名

## 五、数据库与持久层规范

### 5.1 SQL 编写
- **索引**: WHERE、ORDER BY、JOIN 字段必须评估索引；禁止全表扫描
- **分页**: 大数据量必须使用物理分页（`LIMIT` / `ROWNUM`），禁止内存分页
- **批量操作**: 批量插入使用 `INSERT ... VALUES (...), (...)` 或 JDBC Batch
- **N+1 问题**: 使用 `JOIN FETCH`（JPA）或 `collection` 标签（MyBatis）解决
- **SELECT ***: 禁止 `SELECT *`，必须显式指定字段

### 5.2 事务管理
- **注解**: 使用 `@Transactional`（Spring）
- **传播行为**: 根据业务选择 `REQUIRED` / `REQUIRES_NEW` / `NESTED`
- **只读事务**: 查询方法标记 `@Transactional(readOnly = true)`
- **事务边界**: 事务应放在 Service 层，禁止在 Controller / Repository 开启
- **异常回滚**: 默认回滚 `RuntimeException`，如需回滚受检异常配置 `rollbackFor`

```java
@Transactional(rollbackFor = Exception.class, timeout = 30)
public void transfer(Long fromId, Long toId, BigDecimal amount) {
    // 业务逻辑
}
```

### 5.3 乐观锁 / 悲观锁
- **并发更新**: 优先使用乐观锁（版本号 `@Version`）
- **悲观锁**: 仅用于强一致性短事务（`SELECT ... FOR UPDATE`）

#### 5.4.4 Service 层规范
```java
public interface UserService extends IService<User> {
    // 业务方法声明
    UserVO getUserDetail(Long id);
}

@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User> implements UserService {

    @Override
    public UserVO getUserDetail(Long id) {
        // ✅ 使用 BaseService 提供的 getById / save / update / remove 等方法
        User user = getById(id);
        if (user == null) {
            throw new UserNotFoundException(id);
        }
        return convertToVO(user);
    }

    public void batchUpdateStatus(List<Long> ids, Integer status) {
        // ✅ LambdaUpdateWrapper 构建动态 SQL
        lambdaUpdate()
            .set(User::getStatus, status)
            .set(User::getUpdateTime, LocalDateTime.now())
            .in(User::getId, ids)
            .update();
    }

    public List<User> searchUsers(String keyword, Integer status) {
        // ✅ LambdaQueryWrapper 类型安全查询
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(StringUtils.isNotBlank(keyword), User::getUsername, keyword)
               .eq(status != null, User::getStatus, status)
               .orderByDesc(User::getCreateTime);
        return list(wrapper);
    }
}
```

**Wrapper 使用原则**:
| 场景 | 推荐方式 | 示例 |
|------|----------|------|
| 简单等值查询 | `lambdaQuery()` / `lambdaUpdate()` | `.eq(User::getId, id)` |
| 动态条件 | `LambdaQueryWrapper` | `.eq(Objects::nonNull, User::getStatus, status)` |
| 复杂 SQL | XML 编写 | 多表 JOIN、子查询 |
| 批量操作 | `saveBatch` / `updateBatchById` | 默认批次 1000 |

#### 5.4.5 分页规范
```java
@Configuration

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {

        // 分页插件

// 使用
public IPage<UserVO> getUserPage(int current, int size, String keyword) {
    Page<User> page = new Page<>(current, size);
    LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
    wrapper.like(StringUtils.isNotBlank(keyword), User::getUsername, keyword);

    IPage<User> userPage = page(page, wrapper);
    // 转换 VO

}
```

## 六、性能规范

### 6.1 集合与循环
- **容量初始化**: 已知大小时初始化集合容量（`new ArrayList<>(size)`）
- **遍历**: 优先 `for-each` 或 `Stream`；禁止在 `for` 循环中调用 `size()` 方法
- **Stream 使用**: 复杂操作避免嵌套 Stream；注意惰性求值与终端操作

### 6.2 字符串处理
- **拼接**: 循环内禁止 `String +`，使用 `StringBuilder`
- **格式化**: 日志使用占位符 `{}`，禁止 `String.format` 预拼接

### 6.3 并发与异步
- **线程池**: 禁止手动 `new Thread()`，使用 `ThreadPoolTaskExecutor`
- **异步方法**: 使用 `@Async` + 自定义线程池，配置拒绝策略
- **锁粒度**: 尽量减小同步块范围，优先使用 `ConcurrentHashMap` / `ReentrantLock`
- **CompletableFuture**: 异步编排优先使用，注意超时设置

### 6.4 缓存
- **Redis**: 热点数据缓存，设置合理 TTL；禁止缓存大对象（> 1MB）
- **缓存一致性**: 更新数据时先更新数据库，再删缓存（Cache-Aside）
- **缓存穿透/击穿/雪崩**: 使用布隆过滤器、互斥锁、随机 TTL 防护

### 6.5 资源管理
- **Try-With-Resources**: 所有 `Closeable` 资源必须使用
- **连接池**: 数据库、Redis、HTTP 连接必须池化，配置最大连接数与超时

### 7.1 日志级别

### B. Service 模板（MyBatis-Plus + Lombok）
```java
@Service
@RequiredArgsConstructor
@Slf4j
public class UserServiceImpl extends ServiceImpl<UserMapper, User> implements UserService {

    private final UserConverter userConverter;
    private final PasswordEncoder passwordEncoder;

    @Override
    @Transactional(readOnly = true)
    public UserVO getUserById(Long id) {
        User user = getById(id);
        if (user == null) {
            throw new UserNotFoundException(id);
        }
        return userConverter.toVO(user);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public Long createUser(UserDTO dto) {
        // 业务校验
        if (lambdaQuery().eq(User::getEmail, dto.getEmail()).count() > 0) {
            throw new BusinessException(ErrorCode.EMAIL_EXISTS);
        }

        User user = userConverter.toEntity(dto);
        user.setPassword(passwordEncoder.encode(dto.getPassword()));
        save(user);

        log.info("User created, userId={}, email={}", user.getId(), dto.getEmail());
        return user.getId();
    }

    @Override
    @Transactional(readOnly = true)
    public IPage<UserVO> getUserPage(int current, int size, String keyword) {
        Page<User> page = new Page<>(current, size);
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(StringUtils.isNotBlank(keyword), User::getUsername, keyword)
               .orderByDesc(User::getCreateTime);
        return page(page, wrapper).convert(userConverter::toVO);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void updateUserStatus(List<Long> ids, Integer status) {
        lambdaUpdate()
            .set(User::getStatus, status)
            .set(User::getUpdateTime, LocalDateTime.now())
            .in(User::getId, ids)
            .update();

        log.info("Batch update user status, ids={}, status={}", ids, status);
    }
}
```

### C. 全局异常处理模板
```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.warn("Business error: {}", e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
            .map(error -> error.getField() + ": " + error.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return Result.fail(ErrorCode.PARAM_ERROR, message);
    }

    @ExceptionHandler(MyBatisPlusException.class)
    public Result<Void> handleMyBatisPlusException(MyBatisPlusException e) {
        log.error("Database operation failed", e);
        return Result.fail(ErrorCode.DB_ERROR, "数据库操作失败");
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("System error", e);
        return Result.fail(ErrorCode.SYSTEM_ERROR, "系统繁忙，请稍后重试");
    }
}
```
